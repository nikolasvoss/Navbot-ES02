Hardware notes

Planned UART2 uses J8 pin 7 (GPIO4 TX) and pin 29 (GPIO5 RX). The module TX connects to RX only after its signal level is checked.

Use J8 pin 4 for 5 V and pin 6 for ground only after supply and current checks. No motor GPIO or PWM output is enabled.

Reported measurements: M− is 5 V idle and needs an external transistor sink, not a direct GPIO connection. TX reads 1.8 V on a DMM; its UART high and low voltages still need a waveform measurement.

Angle zero and direction are native and uncalibrated. See docs/ros2_pc/hardware/lds08rr-lidar.md for setup and evidence.

Software uses lds2d[viz]==0.7.0; the selected protocol and device path must be confirmed for the connected sensor.

Delta and Camsense support is temporary. TODO: remove the unused project variant after a capture from this module identifies its protocol and the selected driver produces valid scans.

Software and UART setup

On the robot, install ROS 2 Jazzy and create the documented Python environment:

python3 -m venv --system-site-packages "$HOME/.venvs/navbot-lidar"
source "$HOME/.venvs/navbot-lidar/bin/activate"
python -m pip install 'lds2d[viz]==0.7.0'

Run these commands from the project checkout. Use --demo to check the page without hardware:

python scripts/start_lidar.py --demo --host 0.0.0.0

After confirming the protocol and serial device, replace --demo with --device /dev/ttyAMA2 --protocol camsense or --protocol delta as appropriate. Source /opt/ros/jazzy/setup.bash to enable ROS output.

UART2 is planned for GPIO4/TX on J8 pin 7 and GPIO5/RX on pin 29. Confirm supply, ground, connector mapping, and signal voltage before wiring. Only then enable dtoverlay=uart2-pi5; verify the pin mux and identify the resulting /dev/ttyAMA* mapping instead of assuming its name.
